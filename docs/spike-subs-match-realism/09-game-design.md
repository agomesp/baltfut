> Grounded in the actual `/subtests` spike: today the whole game lives in one `useState<DraftState>` in `src/app/subtests/page.tsx` — lobby → draft → done → bracket, all in-memory, single-browser, single-player, zero persistence, zero identity. The engine (`src/lib/subs-draft/`) is genuinely good: `simulateMatch` uses Poisson goal counts weighted by XI strength, cards/injuries fold into a `StatusMap` that carries suspensions across rounds. The gap is entirely the *loop* — nothing makes a sub come back, and nothing makes a match a shared event. That's what this ranks.

## The core problem to solve first

The engine already produces believable *matches*. But a believable **competition** needs three things the spike lacks: (1) a shared clock so everyone watches the *same* match at the *same* moment, (2) persistent identity so a sub's team is *theirs* across sessions, and (3) stakes that tie back into the existing palpites points. Believability of the *loop* is a social property, not a simulation one — FM/Football Manager feels real because of the season narrative, not the 2D match engine. Copy that.

## Ranked upgrades

### 1. Persist the draft + tournament state to Supabase (unlocks everything). Effort: M. Runs: Supabase.
Everything below depends on state surviving a refresh and being *shared*. Add tables `subs_leagues`, `subs_teams` (owner identity, code, roster JSONB), `subs_bracket` (rounds JSONB), `subs_status` (StatusMap JSONB). The pure engine functions already take-and-return immutable `DraftState`/`Bracket` — persist the serialized blob per league, not per-mutation, so you keep the pure-function architecture. **Why it boosts realism:** a team you drafted three weeks ago that's still standing in the quarters is the entire emotional hook — it's *yours*, it has history. **Tradeoff:** RLS must gate writes. Follow the project's existing pattern (SECURITY.md invariants): reads via `security_invoker` views, writes only through an Edge Function like `cast-vote`, never anon-writable. This is the one that pays for all the others.

### 2. Server-authoritative match clock via Realtime broadcast (the "watch party"). Effort: M. Runs: needs-server (or Edge Function + cron). 
The KNOWN LIMITATION — rAF freezes in a background tab — is fatal for a *shared* watch. Fix it by making the match a **timeline, not an animation**: `simulateMatch` already precomputes every `MatchEvent` with a minute. Store the precomputed result plus a `kickoff_at` timestamp. Every client computes `currentMinute = (now - kickoff_at) / secondsPerMinute` and renders the timeline up to that minute. A backgrounded tab that wakes at minute 78 simply *catches up* — no freeze, no drift, perfect sync across all viewers. Push minute ticks / goal moments over **Supabase Realtime broadcast** so even idle tabs get a notification. **Why:** this is what turns 40 solo simulations into one appointment event the streamer counts down to. **Tradeoff:** you need *something* to set `kickoff_at` on schedule — a `pg_cron` job on Supabase or a cheap cron worker (Cloudflare Worker free tier / a $5 Fly.io box). This is the single biggest "feels like a real match happening now" lever. **Quick-win variant:** even without a server, deriving the render minute from wall-clock instead of rAF is a client-only S fix that kills the freeze bug for a solo viewer.

### 3. Twitch/Kick identity + sub-gating. Effort: M. Runs: needs-server (OAuth).
A static site can't hold an OAuth secret, so run the token exchange in a Deno Edge Function (you already deploy one). Twitch OAuth → verify `channel:read:subscriptions` / check the user is a sub of the streamer's channel → mint a short-lived signed session the client stores. **Why:** "sub-only" is the entire value proposition — the team belongs to a real person the chat knows, rivalries become real ("Gabriel's Brazil vs the mod's Argentina"). **Tradeoff:** Twitch sub-status API needs the *broadcaster's* token; simplest cheap path is the streamer authorizes once and a tiny worker caches the sub-list hourly. Kick's API is less mature — treat Twitch as primary, Kick as best-effort. **Trap:** don't gate *drafting* behind OAuth on day one; let anyone spectate, gate only *owning a team*, or you kill the funnel.

### 4. Tie match outcomes into the existing palpites points system. Effort: S–M. Runs: Supabase.
The main app already has `classifyPrediction`/`rankPredictions` and a points model. Reuse it verbatim: before each subs match kicks off, open a **palpite window on the fictional match** (exact scoreline, MVP, pen-winner — the pen-winner feature already exists in prod per memory). Non-owners bet on subs matches; owners earn bonus points when their team wins. **Why:** it fuses the two games into one economy — the passive palpites audience now has a reason to care about the fantasy tournament, and vice-versa. This is the highest ROI integration because the machinery exists. **Tradeoff:** the server-side cutoff logic (memory: `cast-vote` rejects post-kickoff) must key off the subs match's `kickoff_at`, not ESPN.

### 5. Channel-points / bits betting + MVP votes during the match. Effort: M. Runs: needs-server.
Twitch **Channel Points custom rewards** + **Extensions/PubSub** (or Kick equivalents) let viewers spend points to predict the scorer, vote live MVP, or trigger a "clutch moment" poll at 85'. Twitch's built-in **Predictions API** is purpose-built for this — a bot opens a prediction at kickoff, resolves it from your authoritative scoreline. **Why:** channel-points betting is *the* proven Twitch engagement primitive (every big streamer uses it); it converts spectators into participants with zero cost to them. **Tradeoff:** needs a persistent bot process (EventSub websocket) — a $5/mo worker. **Quick win inside this:** live MVP vote is just a Realtime broadcast tally with no Twitch dependency — ship that first.

### 6. Season persistence: growth, carryover, dynasties. Effort: M–L. Runs: Supabase.
The `StatusMap` already carries cards/injuries/suspensions across rounds (`advanceStatus`/`applyMatchEvents`). Extend to *seasons*: winners' players get a small rating bump, a transfer/re-draft window between seasons, retained-core rules, a "dynasty" badge for repeat champions. **Why:** FM/EA FC retention is almost entirely the multi-season arc — the same names improving/declining creates attachment no single tournament can. **Trap:** don't build promotion/relegation *leagues* before you have >1 full tournament actually played — that's premature structure (an L for uncertain payoff). Sequence it *after* #1–#5 prove the loop.

### 7. Standings, awards & shareable results. Effort: S–M. Runs: client + Supabase.
Golden Boot, Golden Glove, tournament MVP, biggest upset — all derivable from the stored `MatchEvent[]`. Render a post-match / post-tournament **shareable card** (static SVG → PNG via canvas `toDataURL`, client-only) the sub can drop in chat/Twitter. **Why:** shareable outcomes are free acquisition; "MY team won the cup" clips are the loop's viral surface. **Quick win:** the award computation is pure over existing data — an afternoon.

### 8. Narrative layer: streamer-as-commentator + rivalries. Effort: S (data) / ongoing. Runs: Supabase.
Auto-generate storylines from data the sim already emits: "revenge match" (beat you last round), "giant-killer" (low avg-rating team still alive), "cursed from the spot" (lost on pens twice). Surface them as ticker lines feeding the streamer's commentary. **Why:** narrative is what makes 40 dot-tokens feel like a *story*; it costs almost nothing because the events already exist in `MatchResult.events`.

## Quick wins vs traps

- **Quick wins:** wall-clock-derived match minute (#2 client variant, kills the freeze bug), palpites reuse (#4), award computation (#7), narrative tags (#8), live MVP tally (#5 subset). All are S and mostly pure over data you already have.
- **Traps:** building multi-season leagues/promotion-relegation (#6/beyond) before one tournament has been *watched together*; hard-gating the funnel behind OAuth (#3) too early; investing more in the 2D sim's visual fidelity while the *loop* has no persistence — polishing the play when nobody has a team to root for is effort in the wrong place.

## Where it must run — summary

**Supabase-only** (no server): state persistence (#1), palpites tie-in (#4), standings/awards (#7), narrative (#8), MVP tally. **Needs a cheap server/worker** ($5/mo Fly/Cloudflare, worth it): the scheduled `kickoff_at` clock (#2), Twitch OAuth + sub-check (#3), the channel-points/predictions bot (#5). Given the small-budget allowance, one tiny always-on worker unlocks #2/#3/#5 together — that's the single highest-leverage paid dependency, and I'd greenlight it once #1 and #4 are live and the loop has proven it holds subs' attention.

**Recommended sequence:** #1 → #4 → #2 → #7/#8 → #3 → #5 → #6.
