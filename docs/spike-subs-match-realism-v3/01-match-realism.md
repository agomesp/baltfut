# Match Realism V3 — Sim Engine, Physics, Player Bodies & AI

## 1. What the two spikes got right, wrong, and missed

I re-read the actual engine (`match-sim.ts`, 673 lines), the IK prototype (`pitch-view.tsx`, `/subtests2`), and all four theme docs. The single most important grounding fact both spikes state but neither *fully* internalises: **there are two disconnected models**. `tournament.ts::simulateMatch` decides the scoreline by Poisson-from-average-rating and `scoreFor()` scripts a ball into a corner (`match-sim.ts:637`), while the on-pitch sim is pure cosmetic theatre reading `Math.random()` ~40 times. V1's simulation doc (item #2) names this correctly as "the highest-leverage work here," and V1's ball doc and V2's AI doc both circle it. **They are right, and it is still the thing to fix first.**

**What holds up:**
- **Utility AI over the FSM (V1 sim #1, V2 AI Tier 1).** Both are correct that `decide()` (`match-sim.ts:307-390`) is already a half-written utility function — line 357-363 literally scores mates by `ahead*1.1 + defenderDist − carrierDist*0.25 + rnd(0,6)`. V2's "finishing a job the code half-started" is the most honest framing. The "days, high ROI" estimate is the one estimate that survives.
- **Ball z-axis as the biggest single physics jump (V1 physics #1).** Correct and under-appreciated by the AI-centric docs. Every cross, corner, header, goal-kick is currently a flat grass-drag (`doCross`, `distribute`, `shoot(header)` all set only `vx/vy`). The `drawBall` shadow scaffolding already exists (`pitch-view.tsx:438`) but there's no `z` to drive it — the shadow is a lie.
- **Keep the bespoke integrator, reject matter.js/rapier client-side (V1 physics library section).** Correct: no 2D solver models height, and an emergent solver *fights* a scripted scoreline. This is a genuinely good call that saves a wrong turn.
- **The determinism keystone + integer authority (V1, restated forcefully in V2 anim/AI).** `Math.exp`/`hypot` aren't bit-identical across engines; the body layer must stay cosmetic and read-only. V2's animation doc states this guardrail explicitly ("the skeleton is a pure function of the current cosmetic snapshot; keep it out of the authority path") — and the prototype **already obeys it** (`pitch-view.tsx:8-13` comment + finite-difference velocity derived in the render layer, never fed back). That is the best-executed idea across both spikes.
- **RL self-play is a parked research spike, not a feature (both docs).** Correct, and for the right reason: it optimises "score goals" against an already-decided scoreline, so its emergent output must be overridden. V2's AI doc grading its own sibling's "weeks" as "optimistically wrong by an order of magnitude" is the sharpest self-critique in the set.

**What's over-optimistic / under-scoped:**
- **"Convincing IK in weeks."** V2's animation doc corrects its sibling's "days" to "3-5 weeks," and looking at the prototype, even *that* is optimistic for *convincing*. The foot-plant gait in `stepGait` (`pitch-view.tsx:255-300`) is a real first pass, but it has no z-lift tied to a real ball, no kick/tackle poses, no turn-in-place, and `swingT` cadence is eyeballed. Convincing foot-lock that never ice-skates across *starts, stops, turns, and collisions* is a multi-month tuning problem, not weeks. The spikes budget the happy path (steady-state running) and omit the transitions, which is where procedural gait always breaks.
- **"Utility AI in days" — true for the carrier, under-scoped for off-ball.** The carrier decision is ~80 lines. But V2's Tier 1 quietly expands scope to *all 22 players* scoring `press/mark/run/overlap/drop` — that's a rewrite of `target()` (`match-sim.ts:400-446`), which is currently role-band heuristics, not a utility system. "Days" covers the carrier; the off-ball utility layer that actually makes teams *look coordinated* is weeks.
- **The outcome-bias problem is named but not solved.** V2's AI doc raises the killer subtlety — "better AI looks *unjust*" when good play contradicts the Poisson result — and proposes "nudge the losing team's conversion utility down." That's a hand-wave. It needs a real mechanism (see §2, the unified xG model), and neither spike specifies it concretely.

**What's missing entirely from both:**
1. **Animation state driven *by the sim*.** The prototype infers everything (facing, stride, lean) from finite-differenced position. But `match-sim.ts` *knows* the semantic event — it called `shoot()`, `foul()`, `giveBallTo()` (tackle). None of that reaches the body layer. There is no kick pose, no tackle lunge, no header jump, no goal celebration, no ragdoll on `foul()` (`match-sim.ts:249`). The bodies move like joggers who never touch the ball. **A one-way, cosmetic "animation event" channel from sim → renderer is the missing seam** and it's cheap.
2. **Ball z fully wired to gameplay.** Not just render lift — headers should only connect in a head-height zone, keepers claim high balls, half-volleys exist. The sim has none of this.
3. **Momentum-conserving contact.** `separate()` (`match-sim.ts:472`) is a symmetric soft-push; there's no shielding, no strength-weighted 50/50, no shoulder-to-shoulder. Hold-up play and duels read as "two dots politely repelling" (V1 physics #5 names it but ranks it low).
4. **Turning radius / reaction lag.** `steer()` (`match-sim.ts:448`) caps linear accel but pivots are free — players reverse instantly ("hockey air-bots," V1 physics #3). Missing from the AI docs entirely.
5. **Set-piece / goal-type variety.** `scoreFor()` always tucks into a corner. Watching several matches together, repetition is the immersion-killer (V1 sim #7).

**Where the spikes disagree:** V1's ball doc says "keep the bespoke integrator, reach for rapier2d *only* if you go server-authoritative." V2's AI/anim docs are more emphatic that determinism forbids float-heavy layers in the authority path at all. These reconcile cleanly: **rapier/heavy float sim can live server-side (Bucket B) as the authority; the client body layer stays cosmetic float (any bucket).** The real disagreement is tonal — V2 treats "watch together" as already-decided architecture; V1 treats it as an upgrade. V3 resolves it: seed-broadcast is Bucket A, server-authoritative is Bucket B, and you do the former first.

## 2. The definitive long-game plan (no time limit, done properly)

The spine is: **unify the two models behind one seeded, chance-based engine; make the sim emit semantic animation events; give the ball a z-axis; then layer bodies and (eventually) learned agents on top — always keeping authority integer and cosmetics float.**

### BUCKET A — $0, current stack (GitHub Pages + Supabase free + Actions)

Everything on-field that matters is Bucket A. It runs in a client rAF loop, costs nothing to host, and the "watch together" sync rides existing Supabase Realtime by broadcasting a seed. Ranked:

**A1 — Seeded PRNG + fixed-timestep accumulator (keystone, do first).** Replace every `Math.random()` in `match-sim.ts` *and* `tournament.ts` with one `mulberry32` stream keyed on `(matchId, seed)`; wrap `step()` in a fixed 1/60s accumulator with render interpolation. *Bucket A because* it's pure TS, no infra. *Why it must be A1:* it's the prerequisite for replay, testing, the background-tab fast-forward fix, AND cross-client "watch together" — every client replays the identical match from a broadcast seed. **Effort S (hours).**

**A2 — One shared xG/chance model unifying sim + scoreline.** Build `xgOf(x,y,defendersInCone,keeperAngle)` (logistic on distance+angle, StatsBomb-style). Use it in `decide()`'s shoot utility AND to *derive `tournament.ts`'s goals* — accumulate per-possession xG, sample goals from that instead of raw Poisson. *Bucket A:* ~96-coefficient model, pure math. *Why top-priority:* this is the fix for the "two disconnected models" root problem and it *dissolves the outcome-bias hand-wave* — if the pitch generates the chances that generate the score, play and result agree by construction. Scorelines cluster like real football (many 1-0/2-1, rare 6-0). **Effort M.**

**A3 — Utility AI for the carrier (integer-scored, softmax-via-lookup selection).** Rewrite `decide()`'s coin-flip cascade into `scoreOptions()`: `shoot=xG`, `pass_i=openness − interceptRisk + xT-progression`, `dribble=space − pressure`, `cross=width×boxTargets`, `clear`. Add the **intercept-risk term the code lacks** (perpendicular distance of each opponent to the pass segment × closing velocity) — currently passes fire blind and only check interception mid-flight (`match-sim.ts:572`). Selection: scaled-integer utilities + a 256-entry integer exp lookup so it's deterministic. *Bucket A:* zero deps. *Why:* converts Brownian dots into "a team with a plan," legibly. **Effort M (3-5 days).**

**A4 — Ball z-axis (`z`, `vz`, gravity, bounce) + Magnus curve.** Passes stay z≈0; crosses/corners/goal-kicks/lofted through-balls launch with `vz`; headers connect only in a 1.7-2.4 head-zone; keepers claim high balls. Add a `spin` scalar applying lateral accel perpendicular to velocity so free-kicks/corners/finesse shots *bend*. Wire real `z` into the already-drawn shadow (`pitch-view.tsx:438`). *Bucket A:* point-mass projectile math, ~40 lines. *Why:* the single biggest *physics* believability jump; makes aerial play, headers and the keeper's world legible. **Effort M.**

**A5 — Sim→renderer animation-event channel (the missing seam).** Add a cosmetic, read-only event queue: when the sim calls `shoot`/`foul`/tackle-`giveBallTo`/header/goal, it emits `{playerId, kind, dir, t}`. The body layer plays a kick wind-up + follow-through, a tackle lunge, a header jump, a ragdoll-on-foul (switch the fouled skeleton to free Verlet for ~0.8s on `foul()` at `match-sim.ts:249`, then blend back), a goal celebration. *Bucket A, one-way only* — it never feeds back, preserving integer authority. *Why:* the prototype bodies currently never *interact* with the ball; this is what sells "he kicked it" vs "he jogged past it." **Effort M.**

**A6 — Off-ball utility + formation block with a line of engagement.** Rewrite `target()` around three game-state scalars (defensive-line height, compactness, width); press only past a y-trigger, else hold a mid-block; feed live scoreline+`progress` into the scalars (trailing team late pushes up, leader shuts up shop). *Bucket A.* *Why:* the current "nearest-2 chase always" (`match-sim.ts:616`) reads as chaos; a holding block that springs a press reads unmistakably as real defending and makes the coded offside trap visibly meaningful. **Effort M.**

**A7 — Player kinematics: turning-radius clamp, reaction lag, attribute-split.** In `steer()`, cap angular velocity-vector change (arc, overrun, cut back) and add per-player `reactionDelay` (80-250ms by rating); split `pace` into `topSpeed/acceleration/agility` so the draft's ratings are *visible* on the pitch. *Bucket A.* **Effort S.**

**A8 — Momentum-conserving jostling + shielding.** Replace symmetric `separate()` with mass/strength-weighted contact along the normal; carrier shields by putting body between ball and challenger. *Bucket A, ~30 lines, stays deterministic.* **Effort M.**

**A9 — 2-bone IK gait hardening + kick/tackle/turn poses + set-piece variety.** Extend the prototype's `stepGait`: foot-lift arc, cadence-vs-speed retuning across start/stop/turn, plant-slip prevention, plus explicit kick/tackle/header poses driven by A5's events. Add a goal-type library (header, tap-in, screamer, penalty, deflection) chosen by build-up, consistent with the authoritative scorer's role. *Bucket A, but this is the multi-month tuning item* — budget accordingly, it's the "convincing" the spikes under-priced. **Effort L (weeks-months).**

**A10 — Calibrated event-rate regression test.** 100-sim assertion that pass% (78-88%), shots (10-14/side), corners (~5), foul→card ratio land in real bands. *Bucket A.* Guards A2-A8 from regression. **Effort S.**

**A11 — Offline-fit xG/xT coefficients via a GitHub Action (still A).** Fit the A2 logistic and the xT grid on public event data offline, *commit the coefficients as plain JSON* — no runtime ML dependency. *Bucket A because* the Action is free CI and the artifact is just numbers; this is V2's "Python factory → thin TS inference" pattern at its cheapest. **Effort M.**

### BUCKET B — + one cheap server ($2-25/mo: Fly/Hetzner, Cloudflare DO, or Supabase Pro)

Bucket B is *not* required for on-field realism — everything above is A. B unlocks exactly three things the client can't do:

**B1 — Server-authoritative live sim loop.** Run the (now deterministic, A1) sim once on a cheap always-on server or a Cloudflare Durable Object and broadcast state, so a **backgrounded/occluded tab that freezes rAF re-syncs to server clock** instead of drifting — and everyone provably sees the identical match even if a client tampers. *Needs B because* Supabase free pauses after 7 days idle and a static site has no authoritative clock; a $5 box or DO gives continuous, tamper-proof truth. *Here* rapier2d-WASM's cross-platform determinism finally earns its weight (you still hand-roll ball-z). *Moves here from A:* only the *authority*; the client body/cosmetic layer stays in A.

**B2 — Scheduled kickoffs + heavier continuous fit.** A cron on the cheap box (vs Supabase pg_cron's constraints) can drive scheduled tournament kickoffs and run heavier periodic xG/xT re-fits than a free Action window allows. *Needs B* for the always-on scheduler and longer compute.

### BUCKET C — + GPU (owner's RTX 3060 12GB)

C unlocks only what B provably can't: *learned emergent behaviour* and *live in-browser ML/high-fidelity rendering*. Honest verdict: for on-field realism, C is mostly a research tier, and the 3060 (12GB, mature CUDA) beats the 5060 (8GB, bleeding-edge) for training.

**C1 (mode i — home GPU feeds the server, offline) — MARL self-play → quantised ONNX, off-ball movement ONLY.** Train PPO/MAPPO in a PettingZoo/Gymnasium football env (gfootball is the precedent), export a tiny int8 ONNX policy, run it in-browser via onnxruntime-web batched (22 agents = one tensor/frame). *Needs C because* self-play training is GPU-bound and infeasible on free CI. *The hard constraints the spikes surface:* (a) it **fights the authoritative scoreline** — scope it strictly to off-ball runs/positioning, never to shots/goals, so it can't contradict `tournament.ts`; (b) float matmuls **break cross-client determinism** unless int8-quantised *and* the onnxruntime backend is pinned; (c) high failure risk — "looks weird before brilliant, often never brilliant." **Verdict: a spike, not a roadmap item.** Utility AI (A3/A6) buys ~80% of "alive" for ~5% of the effort.

**C1 (mode i, safe variant) — GPU trains, commits artifacts, GPU then off.** The *defensible* GPU use: offline-train a small **imitation-learning off-ball movement policy** or better xG/xT weights, commit as JSON/int8 ONNX, ship static. No live GPU, no quota risk, no uptime concern — this is just A11 with a bigger model. *Needs C only for the training run.*

**C2 (mode ii — streamer's GPU runs heavy things LIVE in the browser).** WebGPU via onnxruntime-web for live policy inference, or high-fidelity procedural rendering (skinned pixel-art limbs at scale, many-particle turf/crowd, larger sim). *Needs C because* it exceeds a phone viewer's CPU/GPU budget — but it only benefits *the streamer's own machine*, so treat it as a **broadcast-quality render mode**, not the shipped experience. Tradeoff: it's per-device, non-deterministic, and must stay cosmetic; the authoritative match still comes from A1/B1's seed.

**Honest GPU tradeoff summary:** a *live* residential-GPU producer feeding Supabase is redundant against seed-broadcast (A1) and blows the free quota — keep it OFF. The GPU's only justified role is **offline artifact production** (C1-safe) and the streamer's **local broadcast-fidelity render** (C2). Emergent learned agents (C1) remain a parked spike because they fight the scripted scoreline.

## 3. Ranked bottom line

Do **A1 (seed) → A2 (unified xG) → A3 (carrier utility AI) → A4 (ball z + Magnus) → A5 (sim→body animation events)** in that order — those five fix the root "two disconnected models" problem, the biggest physics gap, and the "bodies never touch the ball" gap the prototype exposes. Then **A6-A10** make it feel like a real 90 minutes, and **A9** is the honest multi-month "convincing bodies" grind both spikes under-priced. **B** buys tamper-proof continuous sync and scheduling but nothing on-field. **C** is offline artifact production plus a streamer-only broadcast render; learned emergent agents stay a spike because they fight the authoritative scoreline. The two guardrails that govern everything: **authority stays integer/seeded; cosmetics (bodies, curve, celebrations) stay float and one-way.** The prototype already respects this — build outward from it, don't rewrite it.
